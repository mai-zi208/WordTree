## 1. 整体形态

四层，每层只依赖下一层：

```
浏览器  Vue 3 SPA（hash 路由，无状态库）
          ↓ fetch /api/*
路由层  FastAPI routers/{families,study,generation,images,settings}.py
          ↓
业务层  scheduling.py（排期）· question_builder.py（出题）· agents/*（智能体）
          ↓
数据层  repositories.py（纯 SQL）→ db.py（连接/建表/迁移）→ SQLite 单文件
```

一个进程同时给页面和接口：`web/dist` 存在时，`app/main.py` 末尾把它挂在 `/`（注释里写明了必须最后挂，否则 `/` 会吃掉后面的路由）。路由用 hash 模式，所以不需要 SPA fallback——`#/family/3` 这种路径浏览器根本不会发给服务器。

只监听 `127.0.0.1:8000`，无账号、无鉴权、不部署到公网。这条决定了后面很多"偷懒"是安全的：出题接口直接返回答案（`items[].answer`），前端不作弊防护；`/api/settings` 明文写 `.env` 也不担心被远程调用。

启动顺序在 `lifespan` 里：建表 → 种子数据 → `sweep_jobs()`。最后一步是兜底：用户直接关浏览器时前端来不及丢弃暂存的词族，超 24 小时的任务行由启动清扫解决。

## 2. 数据模型

`db.py` 里四张表，不用 ORM，开 WAL，外键开启：

| 表 | 职责 | 关键约束 |
|---|---|---|
| `families` | 词族主表 | `root` UNIQUE；`kind` 分 `root`（词根族）/`theme`（主题族）；`source` 分 `seed`/`agent` |
| `words` | 族内单词 | `word` UNIQUE（全库不重复，这是"重复词根被拒绝"的实现处）；`content_type` CHECK 限 `sentence/story/passage`；`position` 保留展示顺序 |
| `reviews` | 复习进度 | 主键是 `word` 而不是 id，级联删除跟着词走 |
| `generation_jobs` | 异步任务 + 暂存内容 | `status` CHECK 四态；`result_json` 里躺着还没被用户确认的词族 |

**迁移策略**：`CREATE TABLE IF NOT EXISTS` 对已存在的表不会补列，所以 `EXTRA_COLUMNS` 逐列 `ALTER TABLE ADD COLUMN`。`kind` 这一列就是这么加的第二轮（主题族后于词根族）。老库不用重建。

**词库与进度分离**：`DELETE /api/study/progress` 只清 `reviews`，词库一个字不动。用户界面上"清空进度"的说明文案也是这么写的。

**图片双目录**：手绘种子图在仓库根 `assets/`（只读，永不覆盖），智能体生成的图在 `backend/data/images/`（git 忽略）。两者分别挂在 `/assets` 和 `/media`，库里存的相对路径就是 `assets/xxx.png` / `media/xxx.png`，序列化时 `as_url()` 补一个前导斜杠。

## 3. 记忆模型：间隔重复

`backend/app/scheduling.py`，整个文件 50 行，纯函数、不碰数据库，所以能单独推理。

```
INTERVALS = [0, 1, 2, 4, 7, 15, 30]   # 天，7 档 stage
ROLLBACK_MIN = 3
RATINGS = ("fast", "back", "long", "gone")
```

四档自评怎么推 stage（`next_stage`）：

| 自评 | stage 变化 | 语义 |
|---|---|---|
| `fast` 秒对 | +1 | 稳，往长间隔走 |
| `back` 想起来了 | stage<4 才 +1，否则原地 | 4 档之后不再加速，避免一路冲到 30 天 |
| `long` 想了很久 | `max(stage, 1)` | 不许后退，但也不前进 |
| `gone` 完全忘了 | 回到 1 | 同时 `wrong += 1` |

`apply_rating()` 把 stage 夹在 `len(INTERVALS)-1`，所以永远不会数组越界。

**族级回退**：一次提交里同一个族被自评 `gone` 的词 ≥3 个，整族 `stage>1` 的词一律降回 stage 1（下次间隔 1 天）。动机是"这一族整体没走通，别让它各走各的"，所以回退的是族，不是那个词。实现上 `rollback_family()` 用 `WHERE word IN (SELECT word FROM words WHERE family_id=?) AND stage>?` 一条 SQL 完成，`study.commit` 回读真实进度再返回给前端，保证收工页说"X 月 X 日回来"和库里一致。

`wrong` 记在词上（跨会话累计），族级回退只看**单次会话**的 `gone` 数——这两个决定在需求说明书 §3 末尾的差异表里有记录，是按旧版**运行行为**迁移的，不按旧文档文字。

## 4. 出题引擎

`question_builder.py`。五种题型全部零键盘输入：

| kind | 题干 | 选项 | 答案 |
|---|---|---|---|
| `gloss` 看词猜义 | 单词 | 同族词的**中文释义** | 释义 |
| `meme` 看梗反推词 | 联想画面 | 同族**英文原词** | 单词 |
| `cloze` 例句填空 | 例句（目标词换成 `______`） | 英文原词 | 单词 |
| `order` 词块成句 | 提示"按顺序点词块" | 打乱的 token | 整句 |
| `picture` 看图解词 | 简笔画 | 英文原词 | 单词 |

三个刻意的设计：

1. **干扰项只取同族词**。考的是"族内这五个词你到底分没分开"，而不是蒙一个眼生的。副作用是选项长得都很像，所以 `optionNotes` 把每个选项的中文意思一起返回，答完当场对上——这一条是后来补的，之前只有答案有释义。
2. **`picture` 题取决于 `img` 是否有值**（`kinds_for`）。种子族 10 个词有手绘图，智能体生成的族默认无图，所以这一题只在种子族里出现。要让它进新族，就点"配图"。
3. **每个新词强制出一道 `meme` 题**。`build_queue` 里 `if count > 1 and "meme" not in kinds[:count]: kinds[count-1] = "meme"`。动机是验收标准第 3 条：只有"看梗能反推出词"，才说明联想真的挂上了单词，而不只是好笑。

排题量：复习模式每词 1 题，练习新词（`pool=fresh`）每词 2 题。`pool_words` 的 `fresh/due/weak/all` 四种取词池在选不出词时**回退为整族**，宁可不完美也不给前端一个空队列（空队列在路由层是 409）。

`blank` 与 `example` 的变形关系由校验层保证（见下节），所以出题时 `example.replace(blank, "______")` 可以直接用。

## 5. 智能体层（一）：生成词族

链路是三段，中间那段**不落库**：

```
粘一批词或给一个词根
   → POST /api/generate/group     分组（词根族 / 主题族两种 prompt）
   → 前端预览分组，勾选
   → POST /api/generate/batch     逐族生成，结果暂存在 generation_jobs.result_json
   → 前端逐族预览内容，接受/拒绝
   → POST /api/generate/{job}/save   只有这一步写 families/words，写完 delete_job
```

"AI 生成的内容必须用户确认才进词库"是产品红线，所以 `run_batch_job` 全程不碰 `families` 表；`entry["ok"]` 标记单族成败，一族失败不影响其他族；用户不要了就 `DELETE /{job}`，暂存内容随行删除。`_normalize()` 里 `img` 强制 `None`——一族五个词就是五张图，等用户看过内容再按需点配图，别把 token 和钱花在没人看的词上。

**分组**（`group_words`）要处理两种情况：词能串成一个词根（`root` 族），串不起来就只能按共同话题凑（`theme` 族，如 `postwar/upstairs/abroad`）。所以有 `GROUP_SYSTEM` 和 `THEME_GROUP_SYSTEM` 两套提示词，输出要求"词必须原样来自词表、一个词只进一组、凑不满 2 个进 ungrouped"。粘贴上限 `MAX_PASTED=120` 词，`POS_NOISE` 用来剥掉词后面粘来的 `v./n./adj.`。

**硬校验**（`_errors`）是这条路的质量闸门，约 20 条规则，挑要紧的说：

- `root` ≥2 位小写字母；`rootMeaning` 必须含汉字；`intro` ≥8 字符。
- 词根族：`root` 必须原样出现在每个 `word` 里，也必须出现在 `part` 里。主题族不查这条，改查 `part` ≥4 字符（要写出这个词自己的构词拆解）。
- `meme` ≤20 字且必须是中文画面；`gloss` 必须中文。
- 内容块：`ctype` ∈ 三值，`cen` ≥4 个英文词且**不许混中文**，`czh` 必须中文。
- `example` 4–12 个英文词；`blank` 必须原样出现在 `example` 里，还必须是该词的变形（`blank.startswith(word[:-2])`，放行 -s/-ed/-ing/-tion 这类尾巴）。
- 词表模式：少一个词、多一个词都报错。
- 去重：`known` 取全库已有词，再并上**本次批量里已生成好的词**（`extra_known`），否则两族可能各要一次同一个新词，第二族入库时被 `ON CONFLICT(word) DO NOTHING` 静默吞掉。

校验不通过时不是直接失败，而是 `_user_with_errors()` 把错误清单原样喂回给模型再问一次。`store()` 遇到重复词根返回 `None`，路由把它记进 `skipped` 给用户看原因。

HTTP 层约定：没配密钥 → 503（"先在首页右上角的设置里填上"）；词库里没有这个词 → 422；队列空 → 409；没有该任务 → 404。错误文本一律中文，因为它是直接显示给用户看的。

## 6. 智能体层（二）：配图

`image_agent.py` 只服务 DashScope 系多模态接口（`IMAGE_PROVIDER=dashscope` 才启用，默认 `none` 时所有配图入口直接 503）。三处经验性设计：

1. **正向提示词里一个"不要"都不写**。原先把"不要出现文字、不要气泡"写进正向提示，模型反而被禁令勾着把气泡和汉字画进画面。现在正向只写 `meme` 原文 + 一段固定画风（手绘水彩简笔画、淡彩、留白、一张图只画一件事），所有禁令交给 `negative_prompt`（中英双语一份）。中文释义也不能进正向提示——模型中文太强，会把"解码"这种词直接写到画面物件上。
2. **接口回的是几天就过期的 OSS 链接**，所以必须下载回本地再落盘，库里只存相对路径。文件类型按**文件头 magic bytes** 认（PNG/JPEG/RIFF-WEBP），不信 Content-Type；认不出来就报错，不写一张打不开的图。文件名用 `SAFE_NAME` slug 化，天然防路径穿越。
3. **尺寸参数必须是 `1024*1024`**（星号），写成 `1024x1024` 会被接口拒；不传则默认出竖图。

单张图走 `POST /api/images/word/{word}` 同步返回（几秒的事，不建任务）；整族补齐走 `POST /api/images/family/{id}` 后台任务，逐词 try，一张失败不影响其他张，失败的词记在结果里给用户看。轮询跟生成词族共用 `/api/generate/{jobId}` 那套。

`image_endpoint()` 会把兼容模式尾巴（`/compatible-mode/v1`、`/v1`）剪掉再接原生路径，因为用户粘的 base URL 通常是聊天兼容地址。

## 7. 配置与密钥

`config.py` 的模型：**进程环境是底座，`backend/.env` 是用户可编辑层**。

```
effective_env() = _BASE_ENV(启动快照) + parse_env_file()
```

快照 `_BASE_ENV` 存在的理由：`write_env()` 之后 `reload()` 要重算，如果不留快照，上一轮从 `.env` 读进来的值会被当成"进程环境"，用户把某个键从 `.env` 删掉后它反而删不干净。

`write_env()` 按 `EDITABLE_KEYS` 声明的顺序回写（设置页可改的就那五个键），临时文件 + `os.replace()` 原子替换；值里含换行直接抛错，防止粘一个多行字符串把 `.env` 结构写坏。空值表示删除该键。

**密钥不出前端**：`GET /api/settings` 只回 `keyHint = ****后四位`（`masked_key()`），永不回明文；保存时可以带 `verify=true` 顺带 `llm.ping()`（`max_tokens:1` 的一次最小调用）验证 base URL + 模型名 + 密钥三者能不能配起来。`_explain()` 把 401/403/404 翻成可行动的中文（"检查有没有抄错、过期，或者余额用完" / "接口地址或模型名不对"）。

`llm.py` 是唯一底层客户端，同步 `httpx`，配置即时从 `config` 读（不缓存，所以改完 `.env` 不用重启就生效；但用 `python -m uvicorn app.main:app` 不带 `--reload` 起的进程，改了 Python 代码仍要手动重启）。`complete_json()` 强制 `response_format={"type":"json_object"}`，`_extract_json()` 还兜了一层：剥 ```` ```json ```` 围栏、从第一个 `{`/`[` 起切，因为部分中转站会无视 response_format 返回带前缀的文本。

### 7.1 打成 exe 时路径分两家

`config.FROZEN`（`sys.frozen`）一真，路径基准就换掉：

| | 开发态 | 打包态 |
|---|---|---|
| `RESOURCE_DIR`（只读） | 项目根 | `sys._MEIPASS`，即临时解包目录 |
| `STATE_DIR`（可写） | `backend/` | exe 所在目录 |
| 于是 `DIST_DIR` / `ASSETS_DIR` | `web/dist`、`assets/` | 打进包里的同名目录 |
| 于是 `DATA_DIR` / `ENV_FILE` | `backend/data`、`backend/.env` | `./data`、`./.env`（就在 exe 旁边） |

这么切的理由：onefile 的 `_MEIPASS` 每次启动重新解包、退出就删，把 SQLite 或生成的图写进去等于每次开机清空；反过来把 `web/dist` 露在 exe 外面，拷走一个文件就跑不起来。除 `SEED_FILE` 之外所有路径都从这两个基准派生，`SEED_FILE` 靠 `__file__` 落在 `_MEIPASS/app/`，spec 里对应 `--add-data` 的目标目录。

入口是 `packaging/launcher.py`，跟 `python -m uvicorn` 的差别只有四处：起始词库要 `_MEIPASS/starter` → `./data` 复制一次（`DB_PATH` 已存在就什么都不做，绝不覆盖用户进度）、8000 被占就自动往后找空端口、`uvicorn.Config(app)` 传对象而不是 `"app.main:app"` 字符串（冻结后没有可导入的模块名，也不该开 reload）、stdout 接到文件。

**不弹控制台窗口**（spec 里 `console=False`）。窗口省掉了，退出路径就得另给，否则进程只能靠任务管理器杀：

- 日志：`console=False` 时 PyInstaller 给的 `sys.stdout` 是个吞字的 NullWriter，**不是 None**，所以判断条件只能是 `config.FROZEN` 而不是 `sys.stdout is None`。真正的输出全进 `data/wordtree.log`，每次启动覆盖（`"w"`），里面是 uvicorn 的访问日志加两行端口/目录。
- 退出：`POST /api/shutdown` → 延迟 0.6 秒 `os._exit(0)`（先把响应送回浏览器）。前端只在 `GET /api/health` 回 `packaged:true` 时显示首页右下角那颗「退出程序」，命令行方式跑的人不会看见一颗点了会杀掉自己 dev 服务器的按钮。
- 那颗按钮要求带 `X-WordMemo-Shutdown: 1` 自定义头。缺头直接 400：服务只听 127.0.0.1，但任何网页都能对 `http://127.0.0.1:8000` 发简单 POST，加了自定义头就变成必须过 CORS 预检的请求，别处顺手打不动。
- 单实例：`data/wordtree.port` 记下当前端口，启动先探 `127.0.0.1:{port}/api/health`，活着就只 `webbrowser.open` 然后自己退出。`os._exit` 跳过 `finally`，所以这个文件残留是设计内的——探活失败就当作上次被杀了，重新起一个。

密钥不进包：包里没 `.env`，`GET /api/health` 的 `llm` 是 `false`，接收方自己去设置里填。

## 8. API 一览

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/health` | db 路径、LLM/生图是否就绪、当前模型名、`packaged`（是不是 exe 在跑） |
| POST | `/api/shutdown` | 停掉本机服务；必须带 `X-WordMemo-Shutdown: 1`，见 §7.1 |
| GET | `/api/families` | 全部族 + 每族进度摘要 + `dueTotal` + `today` |
| GET | `/api/families/{id}` | 单族详情，不存在 404 |
| GET | `/api/study/due` | 今天到期的词 |
| POST | `/api/study/queue` | `{mode,familyId,pool}` → 一整队列（含答案） |
| POST | `/api/study/commit` | `[{word,rating}]` → 服务端算排期、判族级回退 |
| DELETE | `/api/study/progress` | 清空 `reviews` |
| POST | `/api/generate/group` | 粘一批词/一个词根 → 分组预览任务 |
| POST | `/api/generate/batch` | 选中的组逐族生成，进暂存 |
| GET | `/api/generate/{job}` | 任务状态与进度（group/batch/image 三类共用） |
| POST | `/api/generate/{job}/save` | 把用户挑中的族写进词库 |
| DELETE | `/api/generate/{job}` | 丢弃暂存 |
| GET / PUT | `/api/settings` | 模型配置读写（PUT 可选顺带 ping） |
| POST | `/api/images/word/{word}` | 给一个词配图，同步 |
| POST | `/api/images/family/{id}` | 整族补图，后台任务 |
| — | `/assets/*` `/media/*` `/` | 手绘图 / 生成图 / 前端构建产物 |

入参出参的命名约定：前端一律 camelCase，Python 内部 snake_case，靠 `schemas.py` 的 `_camel` alias generator 单向翻译，`extra="forbid"` 让拼错的字段直接报错而不是被忽略。出参由 `serializer.py` 负责（`word_json` / `family_json` / `family_state`）。

## 9. 前端

无 Pinia、无组件库，只有一个 `reactive` 的 `store.js` + 一个 `api.js`（fetch 封装，网络层失败翻成"连不上后端：先在 backend/ 目录启动 FastAPI"）。

| 路由 | 组件 | 守卫 |
|---|---|---|
| `#/` | `HomeView`（刊头 + 到期提示 + 便签墙 + 两个弹层） | — |
| `#/family/:id` | `FamilyView`（族谱 + 逐词卡片 + 动作区 + 翻页） | 族不存在则回首页 |
| `#/quiz` | `QuizView` + `QuestionCard` + `RatePanel` | 无 `state.session` 则回首页 |
| `#/done` | `DoneView` | 无 `state.summary` 则回首页 |

`scrollBehavior: () => ({top: 0})` 保证换页从顶部开始。守卫的意义是深链不会白屏：直接敲 `#/quiz` 而没答题，会被送回首页而不是渲染一个空队列。

**`wallOrder()` 是一个顺序的两个消费者之间的契约**：便签墙的排布和词族页"上一族/下一族"都从 `store.js` 这一个函数取，没学过的排前面、学过的排后面，组内保持接口给的 id 升序（`sort` 稳定）。任何一处自己排，"下一族"就不是墙上的下一张。相邻族按下标取，不按 id±1，因为被拒绝过的生成任务会让 id 跳号。

**词族页的滚轮翻族**（`FamilyView.vue`）是个小状态机，判定链是：

```
同一个手势（静默 <250ms）→ 文档已顶到边缘 → 继续往外推 → 累计 45px 亮出回显 → 累计 200px 换族
```

阈值来自实测：200px 约等于 Windows 滚轮在边缘再两格，是"故意的推力"，而误触的惯性尾巴通常不到这个数。三重闸门防止一次甩动连翻几族：`spent` 一次性标记（翻完吃掉本次手势）、`GESTURE_GAP=250ms`（重新计账）、`COOLDOWN=600ms`（两次换族的最小间隔）。`deltaY` 按 `deltaMode` 归一化（行 ×33、页 ×视口高），因为 Firefox 报行、分页控件报页。`preventDefault()` 只在往外推的方向上调用，且监听器必须 `{passive:false}`。

换族用 `router.replace` 而不是 push：连翻几族之后，浏览器后退的语义仍然是"回便签墙"。带 `ctrl/meta/alt` 的 wheel 一律忽略（触控板捏合缩放就是这么发事件的）。手机上不做边缘甩动，改页头 `← →` 按钮 + 左右横扫（`|dx| ≥70px` 且横向明显占主导、500ms 内）。

**改路由参数会复用组件实例**，`onBeforeUnmount` 不跑，所以放大图、补图进度这些临时态必须在 `watch(() => props.id)` 里手动清。这条踩过：孤儿大图既不消失又把滚轮一直锁死（`canPage()` 里 `zoomed` 直接判假），fallback 值跟过来会让数据 `resolve()` 早退、页面卡在上一族。同理，整族补图的进度和"应用这张图"绑在发起任务的族上（`jobFamilyId`），翻到别的族时不会被别人的进度盖住当前页的按钮。

`say()` 不是 TTS，它写 `#live` 这个 `aria-live` 区域——读屏和静音场景都能拿到播报，不依赖语音合成。

## 10. 视觉系统与便签墙

`styles/app.css` 一个文件，靠 `:root` 设计令牌驱动（纸白暖色 `--bg/--paper/--ink`、低饱和叶绿 `--accent`、砖红 `--miss` 只用来标答错；间距 `--s1..--s7`、圆角、时长与缓动）。深色模式在 `@media (prefers-color-scheme: dark)` 里重打一份令牌，组件规则基本不动。

便签墙：**一行一张**，卡片宽度 `max-content`（五个词排一行要多宽就多宽），整列贴着最宽那张收、在页面居中；每张卡左上角 `mask` 挖一个 10px 的孔，挂在一根 2px 渐变竖线上（线在卡片背后，只从孔里露出来）。孔沿靠一圈 inset 投影压出纸的厚度。卡片按 8 个互不相同的角度绕孔旋转（`transform-origin:19px 15px`），所以是"吊着的纸"而不是表格。

三个实现坑记在这儿，别再踩：

- **mask 会把 `box-shadow` 连着裁掉**，所以纸面和孔沿的投影一律 `filter: drop-shadow()`。
- **翻页控件和滚轮回显必须 `position:absolute`**，给文档多撑一像素，"滚到底"的判定就自己跑掉了。
- `html{overscroll-behavior-x:none}`，否则左右横扫会被 Android 的边缘后退吃掉。

被否掉的方案：蛇形多列 + `<svg>` 贝塞尔藤蔓连线（要 `getBoundingClientRect` + `ResizeObserver` 量坐标重画，而且多列的视觉顺序跟"没学过的排前面"这个语义打架）；金属鸡眼扣（挂在绳上的纸牌不需要五金件）。

## 11. 已知限制与技术债

- **内容债**：4 条种子词的联想超过 20 字上限（库里现存最长 26 字）。校验只管新内容，不动老数据——词库内容一字没改是这一路的约束。
- **没有入库的自动化测试**。排期全组合、五种题型、任务生命周期这些都用一次性断言脚本在临时库上跑过，但脚本没留在仓库里，回归靠手工端到端 + 浏览器里量坐标。想加的第一件事应该是把 `scheduling` 与 `question_builder` 的纯函数钉成 pytest。
- **视觉未经肉眼确认**：这个开发环境里浏览器视口不可用（截图取不到），便签墙的打孔与挂线、暗档配色属于"坐标验证通过、肉眼未确认"。
- **生成质量不可控**：智能体写出来的联想好不好，只有用户点了"接受"才算数。校验拦得住形式，拦不住无聊。
- **图片跟着机器走**：`backend/data/images/` 被 git 忽略，换设备要重画；OSS 链接几天就过期，本来也存不住。
- **仓库体积**：`assets/` 里 11 张手绘 PNG（10 张词图 + 1 张页头图）共约 15MB，页面上只画到 ≤260px。压成 WebP 能省九成，但那是用户手工放进来的资产，没点头不动。
- **`review` 队列不防作弊**：队列接口直接带答案，只监听 127.0.0.1 才敢这么写。真要上公网，第一件事是把 `/api/study/queue` 的答案拆成提交后才回。
